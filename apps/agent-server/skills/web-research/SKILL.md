# 联网检索与核实流程

适用场景：答案取决于**当前**信息或**外部来源**——最新消息、版本与价格、公开数据、某份文档的说法、别人是怎么做的。

## 为什么要有这个流程

训练记忆里的具体细节（数字、日期、版本、人名）会过期，也会记错；而「答得像真的」比「说不知道」更有害——用户不会去核对一个语气确定的数字。所以：能被检索工具核实的可查事实，一律先查再答。

## 步骤

1. **先判断要不要联网**：与时间无关的稳定常识直接答；属于「时效 / 站外 / 需要可查证据」的，走本流程。
2. **把问题变成可检索的查询**：
   - 拆出关键实体（产品名 / 版本号 / 机构 / 时间范围 / 地区），一次查一个核心点，不要把全部限定词堆进一条查询；
   - 先宽后窄：先看有哪些来源，再针对最相关的那条深挖——拿到页面正文比只看搜索摘要可靠。
3. **多源交叉**：同一事实至少看两个独立来源；一手资料（官方文档、原始数据）优先于聚合站与二手转载。两者不一致时说明分歧并各自给出处，不要挑一个顺眼的报出去。
4. **摘证据而不是搬原文**：只取回答所需的关键信息（数字、日期、结论句），并给出可点击的来源链接。
5. **如实标注确定性**：检索不到、页面打不开、来源互相矛盾都要讲清楚；用「我查到的」与「我记忆里的」区分两者。用户问到的细节若恰好查不到，不要顺手补一个像的。

## 交付格式

- 先给结论（一句）；
- 再给依据：关键事实 + 来源链接（1–3 条足够，不必罗列看过的所有页面）；
- 信息可能变动时标注「截至 <日期>」。

## 注意

- 用户的**内部资料**（公司数据、私有文档、本地知识库）优先走内部检索工具，不要拿去公网搜——数据外发的代价远大于查不到。
- 检索只能核实**事实**，不能证明你理解的指代就是用户想问的那个：关键用词本身不唯一时，先按澄清纪律问清、再检索。
- 不要把「网上没有」当成「这件事不存在」：换个说法、换语言或换信息源再试一次。

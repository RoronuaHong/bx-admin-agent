# 联网检索与核实流程

适用场景：答案取决于外部世界的**当前**信息——最新消息、版本与价格、公开数据、某份公开文档的说法、别人是怎么做的。已连接的自有数据不在此列。

## 为什么要有这个流程

训练记忆里的具体细节（数字、日期、版本、人名）会过期，也会记错；而「答得像真的」比「说不知道」更有害——用户不会去核对一个语气确定的数字。所以：属于本技能适用场景的事实，一律先查再答。

## 步骤

1. **先判断要不要联网**：与时间无关的稳定常识直接答；属于「时效 / 站外 / 外部主体的公开事实」的，走本流程。用 `web_search` 检索，再按需要 `fetch_url` 打开原文。
2. **把问题变成可检索的查询**：
   - 拆出关键实体（产品名 / 版本号 / 机构 / 时间范围 / 地区），一次查一个核心点，不要把全部限定词堆进一条查询；
   - 先宽后窄：先看有哪些来源，再针对最相关的那条深挖——拿到页面正文比只看搜索摘要可靠。
3. **多源交叉**：同一事实至少看两个独立来源；一手资料（官方文档、原始数据）优先于聚合站与二手转载。两者不一致时说明分歧并各自给出处，不要挑一个顺眼的报出去。
4. **摘证据而不是搬原文**：只取回答所需的关键信息（数字、日期、结论句），并给出可点击的来源链接。
5. **如实标注确定性**：检索不到、页面打不开、来源互相矛盾都要讲清楚。这个来源没有的细节就说没有，不要用记忆补上一个像的。

## 交付格式

- 先给结论（一句）；
- 再给依据：关键事实 + 来源链接（1–3 条足够，不必罗列看过的所有页面）；
- 信息可能变动时标注「截至 <日期>」。

## 注意

- 已接入的自有数据走对应的内部技能，不要拿去公网搜。
- 检索只能核实**事实**，不能证明你理解的指代就是用户想问的那个。两种读法会导向不同答案时，按系统提示第 8 条：一次检索能把读法分开就先查，分不开再问。
- 不要把「网上没有」当成「这件事不存在」：换个说法、换语言或换信息源再试一次。仍然没有，就说明这个来源没有该事实，不要改用别的数据源换一个主体来答。

# 业务取数流程

适用场景：用户要一个属于已连接自有业务数据的数字。这是本助手最高频的任务，也是最容易出错的一类：**数字看起来合理就没人会去核对**，所以错口径会被直接带进决策。主体落在外部世界时不要进入本流程，也不要用本流程去验证那个主体是不是自有数据。

流程固定为「先确定问的是什么 → 找存量口径 → 取证 → 取数 → 核对 → 交付」。每一步都有明确的产出，跳过任何一步都可能让后面白做。

## 步骤

1. **先确定问的是什么**：把口径写成三个问题——时间范围（哪天到哪天）、粒度（按天 / 按渠道 / 按用户）、过滤条件（哪条业务线、哪些状态）。三者都会改变结果。口径不唯一时按系统提示第 8 条：检索能把读法分开就先查，分不开再问，不要自己挑一个更常见的。
2. **先找存量口径，再写新查询**：用元数据 / 搜索类工具找同一口径的既有定义（已保存的提问、仪表盘、卡片里的 SQL）。有现成的就以它为基准——同一个指标出现两套算法，比数字本身错更难排查。指标定义互相冲突时，改走「指标口径核对」。
3. **陌生表先取证**：加载并执行「陌生库探查」，不要在这里另写一套探查步骤。结构很大时，委派子代理只把结论带回来。
4. **查询只读、最小代价**：先用一页确认字段，再在服务端或代码里完成聚合。不要把明细行搬进上下文。跨页计数与小时汇总按工具使用纪律执行。
5. **交付前自己核对一遍**：量级对不对（与总量或上次同类结果比）、口径是否就是用户问的那个、有没有 NULL / 空串被静默排除。对不上就查清差在哪，而不是挑一个看起来合理的数字报出去。

## 交付格式

- 第一句给结论：**数字 + 口径**（时间范围 / 粒度 / 过滤条件）。
- 第二句给来源：用了哪张表，或复用了哪个既有定义。
- 可能影响解读的点如实说明（例如"已排除 status 为空的 3 条记录""该字段存在默认值"）。
- 用户要图时再出图；要明细时再给明细行。

## 注意

- 经营数字只从本技能对应的数据连接器取。其它资料库里的文档不能用来证明这个数不存在。
- 本轮工具通道里没有该数据源时，要说「这次对话没有启用对应数据源」，不要说成「系统没有接入」或「账上没有这笔数」，也不要改用其它域补一个数字。
- 业务口径以用户或既有定义为准，不要自己发明口径；用户说了口径就按用户说的算。
- 同一轮里已经确认过的数字不要重复查询，直接复用。

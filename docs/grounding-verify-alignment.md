# 事后核验（Grounding Verify）最佳实践对齐

> 日期：2026-09-30。范围：`src/grounding.ts` 的**事后核验**部分（收束前对「回答 vs 本轮证据」做断言级核对）。
> 只引用公开做法，不把评测基准和工程护栏混为一谈。

**怎么读**

| 标记 | 意思 |
|---|---|
| 已对齐 | 现有行为与所选做法一致，保持 |
| 已落地 | 2026-09-30 已改代码 |
| 维持 | 有理由不做，或代价大于收益 |

---

## 0. 我们现在做的到底是哪一类

四件事常被混为一谈，先分清我们落在哪：

| 做法 | 它在做什么 | 我们的位置 |
|---|---|---|
| **CoVe**（Chain-of-Verification） | 起草 → 生成验证问题 → **独立**回答这些问题（不回看草稿）→ 比对修正 | 目标形态；改前只做到「看着草稿判对错」 |
| **Self-RAG / ISSUP** | 生成时插入反思标记，判「证据是否支持这句话」 | 改前的实现最接近这一类（一步式支持性判定） |
| **FActScore / Attributed QA** | 把长回答拆成**原子事实**，逐条与证据做蕴含判定 | 改后引入（先拆断言，再逐条判） |
| **引用溯源** | 强制带引用 + **系统侧**校验引用是否真的存在 | 已落地（`unknownToolRefs` / `crossCheckSources`） |

---

## 1. 逐步对照

| # | 最佳实践 | 改前 | 结论 |
|---|---|---|---|
| V1 | **验证要独立于草稿**：CoVe 的关键不在于「多问一遍」，而在于回答验证问题时**看不到原答案**，否则模型只是在自我确认 | 一次调用里同时喂「问题 + 证据 + 回答」，让模型判哪些断言无支持——它全程看着自己刚写的草稿 | **已落地**：拆成两段，抽取断言只看回答，判定只拿「证据 + 断言」，**不回传原回答** |
| V2 | **先原子化再判定**（FActScore）：长回答整体打分会漏掉夹在正确内容里的错断言 | 分解与判定在同一步、同一上下文完成，模型既当分解器又当裁判 | **已落地**：阶段一专做抽取，阶段二逐条判 |
| V3 | **可确定性判定的事不交给模型**：来源是否存在是集合比对，不是语义判断 | 来源存在性已有一半确定性（`unknownToolRefs` 直接从回答抽 `mcp__x__y` 比对），但回答里声称的其它来源仍由核验器报 | **已落地**：来源改由阶段一**只抽标识形态**的名称，存在性仍走 `crossCheckSources` 集合比对 |
| V4 | **缓解 LLM-as-judge 的自我偏好（self-enhancement bias）**：同一模型评自己产出的答案，倾向于判「没问题」 | 核验器就是主模型本身（`ctx.model`） | **已落地（可选）**：`GROUNDING_VERIFY_MODEL=<id>` 可指定另一个模型做核验；不配 = 沿用主模型，行为不变 |
| V5 | **判定型调用要确定性**：温度归零，否则同一段回答今天拦、明天放，护栏自己变成随机源 | 已 `temperature: 0` | 已对齐 |
| V6 | **判定型调用不该开着思考链**：输出必须是严格 JSON，推理链只会拖慢并增加跑偏 | 分诊与诚实兜底都 `disableThinking`，**核验漏了** | **已落地**：补齐，与另两个判定调用一致 |
| V7 | **核验器不可用时不阻断作答**（fail-open）：护栏故障不能变成「一律拒答」 | 解析失败/调用异常 → 整体视为未核验；但编造的工具引用仍拦（那条是纯字符串判定，与模型无关） | 已对齐 |
| V8 | **多票裁决降误判**（Self-Consistency）：单次核验可能误报，多数票才认定 | `GROUNDING_VERIFY_VOTES`（默认 1 = 单次） | 已对齐。默认不开：成本随票数线性叠加，「更稳但更贵」应是可选项 |
| V9 | **护栏命中要有可观测信号** | `usage.groundingVerifications` + run trace + 日志 | 已对齐 |
| V10 | **证据预算**：核验不能变成新的上下文负担 | `GROUNDING_EVIDENCE_CHARS`（默认 12k） | 已对齐 |

## 2. 已落地（2026-09-30）

| 编号 | 行为 |
|---|---|
| **V1/V2** | 两阶段核验：①只给回答 → 抽出原子断言 + 声称的来源标识；②只给「证据 + 断言」（**不回传原回答**）→ 逐条判支持性。`GROUNDING_VERIFY_STAGES=single` 可退回一步式 |
| **V3** | 来源存在性全部走确定性集合比对，核验器只负责「抽」，不负责「判存在」 |
| **V4** | `GROUNDING_VERIFY_MODEL=<id>` 指定独立核验模型；未配置 = 主模型（零行为变化） |
| **V6** | 核验调用补 `disableThinking: true` |

开关：`GROUNDING_VERIFY=off` 关总闸，`GROUNDING_VERIFY_MAX`（默认 1）、`GROUNDING_VERIFY_VOTES`（默认 1）、`GROUNDING_EVIDENCE_CHARS`（默认 12000）、`GROUNDING_VERIFY_STAGES`（默认 `two`）。

## 3. 对照证据（本地可复现）

「判定环节不含草稿」这条断言只有在**确实存在一种会把草稿送进判定的形态**时才有意义，所以两个形态各留一个用例，
场景完全一致、只差 `GROUNDING_VERIFY_STAGES`，差异只能来自核验形态本身：

| 用例 | 开关 | 判定输入 | 拦截 |
|---|---|---|---|
| `tests/grounding-verify-two-stage.test.ts` | 默认 `two` | **不含**草稿独有标记（只含被抽出的断言 + 证据） | 拦住并回灌纠正 |
| `tests/grounding-verify-single-baseline.test.ts` | `single` | **含**整篇草稿 | 同样拦住 |

两张表一起说明：去耦改变了判定环节能看到什么，且没有削弱拦截能力（旧形态能拦的，两阶段也拦得住）。

**这两个用例证明不了什么**：它们用 mock 模型，断言的是**形态差异**（谁把什么送进了判定），不是模型质量。
真实模型侧的误判率（漏拦 / 误拦各多少、要不要开多票）必须起真实服务实测——本地 mock 里核验结果是脚本写死的，
误判率恒为 0，拿它当质量结论是自欺。



| 做法 | 为什么不跟 |
|---|---|
| 接一个专用 NLI / fact-check 小模型 | 多一套部署与运维；判定口径已在提示词里写死，收益对我们当前的量级不划算 |
| 默认多票（VOTES>1） | 成本线性叠加，且核验本来只在收束时跑一次；留给「误报确实多」时再开 |
| 用更强的模型做核验（比主模型大） | 与主模型不同族即可缓解自我偏好，不必更大；更大只会更慢更贵 |
| 核验失败就拒答 | 护栏故障不应变成「一律拒答」，见 V7 |

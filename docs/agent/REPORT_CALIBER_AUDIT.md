## 3. 可取之长（建议沉淀进本仓库的报表口径模板）

workbuddy 在**口径纪律**上比我们系统提示里泛泛的要求更具体、更可复用，应写成 few-shot：

- **(A) 故障≠缺数写成"踩坑证据句"**：不空喊原则，直接写"`elt_film_user.country` 字段全空 → 改用 `elt_user_full.countryCode`"、"曾误算 123万 → 正确 75.4万"。这种披露比我们的护栏更有说服力，也更易被审计/复核。
- **(B) 口径冲突双源对照**：把"过期预聚合表 vs 明细表"两种口径摆出来并说明取谁——正是 G 系列护栏要的"口径冲突主动披露"，可作标准范例。
- **(C) 连接键去重陷阱警示**：`uid`（账号）vs `guid`（设备）、设备级宽表必须 `COUNT(DISTINCT uid)`，否则因设备行放大而虚高。这是极易错的口径，应写进口径模板**强制项**。

> ⚠️ **核查更正（2026-10-17 查缺补漏）**：经读 `src/system-prompt.ts` 确认，**(B) 口径冲突主动披露（L120，已含"已过期预聚合表"示例）与 (C) 去重陷阱 `COUNT(DISTINCT <键>)`（L122）本仓库系统提示已具备**，并非缺失——前文"可取之长"把它们当缺口是误判。真正缺失的是 **(A) 的"踩坑证据句"风格**（系统提示无独立 `故障≠缺数` 规则，仅在 `chat.ts` 口径段清单点名）+ **"未覆盖子问题逐条枚举"**（原本只是口径段一个 bullet）。故查缺补漏只补这两项，不重复 (B)(C)。

## 7. 实测对账（2026-10-17，直连 Metabase 只读）

> 为做确定性对账，用与 BI 连接器**完全相同**的 Metabase 只读接口（`POST /api/dataset` + `X-API-Key`，库 id 2，仅 `SELECT`，严守红线不改库）直接取真值，与 workbuddy 报告数字逐条比对。
> 取数口径与 agent 第一轮实跑一致：`vipType=2 AND status=0 AND endDate>now()` 为"当前有效会员"，`uniqExact(uid)` 去重；`elt_active_guid` 按天 `uniqExact(guid)` 为 DAU。

| --- | --- |
| 全量 30 天 DAU（09-17~10-16，按天 uniqExact(guid)） | 谷 **394万**（10-13）～ 峰 **630万**（10-03），30 日均 ≈ **477万** |

### 7.2 逐条对账（workbuddy HTML vs 真值）
| workbuddy 数字 | 真值 | 结论 |
| --- | --- | --- |
| 两国有效会员 **75.4万** | 印度+巴西 77.3万 | ✅ **基本准确**（差 ~2.5%，差在日期窗/定义微调） |
| DAU 峰 467万(10-03) / 谷 336万(10-13)，"约 360~400万" | 全量峰 630万 / 谷 394万；两国必为全量子集 | ⚠️ 数值本身对应"两国"子集、方向合理；但"约 360~400万"措辞与自身"336~467万"矛盾（旧瑕 §4(b) 仍存） |
| 巴西：当前会员 39 / 新 11 / 流 8 / 净 +3 | 巴西注册 **528 人**、有效会员 **26** | ❌ **建立在 ~500 人基数上，可信度极低** |

### 7.3 对账暴露的核心数据准确性问题
1. **workbuddy 的"两国"基本是"印度"**：巴西仅 528 注册、26 会员（占两国合计 0.003%）。所谓"巴西渠道归因（新11/流8/净+3）"是在 ~500 人样本上的噪声——**这是 workbuddy 报告最大的数据准确性盲点**，它把 500 人级别的巴西数字和印度并列成"两国对比"，却没标这个基数警告。
2. **workbuddy 的会员数（75.4万）是真的准**（≈77.3万），且确实写了"故障≠缺数"口径（country 空→countryCode、123万→去重后75.4万）——说明它有基础取数纪律。
3. **分国 DAU 口径不干净**：`elt_active_guid` 只有 `activeDate/channel/guid` 三列、**没有 uid/国家列**。要出"分国 DAU"必须 guid→uid→countryCode 现场关联重算（或退而用 channel 近似，但会被"渠道拆分虚高"污染）。workbuddy 直接给了分国 DAU 却未说明这是近似/关联口径——正是 agent 第一轮主动标注的障碍。

### 7.4 已落地的护栏补强
针对 7.3·1 的"小样本并列成对比"盲区，新增**「小基数隔离」**护栏：
- `src/system-prompt.ts` `ANSWER_SHAPE_EXAMPLE`：新增独立规则——按维度拆分指标时，若某分组样本基数显著小于主群体（低于约 1/10 或绝对值低于约 1 万），**禁止**与主群体并列成"<A> 对比 <B>"结论，必须单列并显式标注样本量，且不得据此下趋势/归因强结论；并在"数据口径与方法"清单中强制列明各分组样本量、哪些因基数过小已单列而非并列对比。
- `src/chat.ts`：补轮提示与收尾提示同步加入"小基数隔离"要求。
- `tests/system-prompt-contract.test.ts`：新增契约断言（`stable` 含 / `bare` 不含 `小基数隔离`）。
- 目的：将来再遇到"印度 vs 巴西"这类主从悬殊的分组对比，agent 会主动把巴西（528 人）单列标注样本量，而不是和印度（1825 万人）并列成"两国对比"误导读者。

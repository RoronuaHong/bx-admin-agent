## 1. 背景与目标

当前后台管理系统本质是一套「自然语言 → 调后台 API → 编排分析 → 可视化/告警」的 Agent 框架。
业务侧希望基于此框架，构建一个**可视化交付型、通用化**的数据分析 Agent：

- 用户用自然语言描述任意分析需求；
- Agent 自动取数、按维度组织、产出**一张张图表**与**可下载的 Excel**；
- 不仅能给文字结论，更能交付可视化产物；
- 投放渠道 ROI 异常监控作为**第一个示范场景**，验证后可快速复制到任意业务指标。

---

## 2. 产品形态定义（通用型）

| 层级 | 说明 |
|------|------|
| 输入 | 自然语言描述分析需求（不写死业务） |
| 过程 | Agent 调数据 API 取数 → 按指标/维度组织 → 选图渲染 |
| 交付物 | ① 多张图表（趋势/对比/漏斗）② Excel 明细下载 |
| 通用化 | 抽象为「指标集 + 维度集 + 图表模板 + 导出」可复用模板 |

**通用能力四要素（模板化）：**
1. **指标集**：可扩展的指标定义（如曝光、点击、ROI…），含口径与预计算规则。
2. **维度集**：可下钻的维度（渠道、语言、包体、日期…）。
3. **图表模板**：数据形态 → 图类型映射（时间序列→折线；分类对比→柱状；链路/占比→漏斗/饼）。
4. **导出策略**：Excel 单表 / 多 sheet / 每图一份。

## 3. 场景一：投放渠道 ROI 异常监控（Demo）

### 3.1 数据需求（每日粒度）

**基础维度**
- 日期：日粒度
- 渠道：fb、tt、gg、apple-ads、自然流、裂变拉新、其它（默认汇总）
- 语言：印度语 / 英语 / 泰米尔语 / 泰卢固语 / 玛拉雅拉姆语（支持下钻）
- 包体：xxxxxx（默认汇总全部，支持下钻）

**指标链路（曝光 → 点击 → 播放 → 支付）**
- 原始量：曝光量、点击量、播放量、支付人数、支付金额
- 比率（建议数据侧预计算）：点击率 CTR、转化率 CVR、ROI

### 3.2 监控逻辑

1. 每日自动计算各渠道 ROI，与**昨日**及**上周同期**对比；
2. 若某渠道 ROI 同比下降 **> 10%** 触发预警（阈值判定建议确定性代码 `ratio < 0.9`）；
3. 预警后自动按**语言 / 包体**等维度下钻，定位具体细分群体。

> 比率指标（CTR/CVR/ROI）口径需与业务对齐，并尽量在数据侧预聚合，避免模型心算误差。

## 4. 系统现状对照（已核代码）

### 4.1 已具备能力

| 能力 | 现状 | 位置 |
|------|------|------|
| 数据接入 | `call_api` 支持 backend/user/film/gather 四类基址，靠 `api-operation-index` 自动发现接口 | `apps/agent-server/src/tools.ts` |
| 图表数据产出 | `summarize_chart_data` 产出 `{categories, series[], title}` 结构 | `tools.ts` |
| 图表渲染 | 前端 ECharts 组件，支持**折线 + 柱状 + 多 series**，多卡片堆叠 | `apps/web/src/components/ResultChart.vue` |
| 表格渲染 | `render_table` | `tools.ts` |
| Excel 导出 | `export_dataset` 支持 `xlsx` / `pdf`，含 footer 合计/均值 | `tools.ts` |
| 枚举映射 | `read_field_mapping` 查渠道等编码枚举，避免模型猜中文 | `tools.ts` |
| 告警通道 | 现有钉钉 Webhook 告警（经 `ALERT_DINGTALK_WEBHOOK`；当前用于预算/劣化告警，业务预警可复用） | `alert-notify.ts` |
| 可观测 | Trace 已记录 Agent 排查过程，便于 demo 复盘 | `trace.ts` |
| 通用编排 | `understand → route_to_agent → call_api → summarize` 不写死业务 | agent-server |

### 4.2 缺口与风险

| 项 | 说明 | 严重度 |
|----|------|--------|
| **转化漏斗图缺失** | `ResultChart.vue` 仅注册 `LineChart` / `BarChart`，**无 FunnelChart / PieChart**；曝光→点击→播放→支付链路无法画漏斗 | 高（必补） |
| **无定时调度** | 全仓无 cron / scheduler（仅 `app.ts`/`chat.ts` 有 `setTimeout` 用于重试退避，非调度）；所有 chat 均用户触发；「每日自动计算 + 预警」需新增调度层 | 高（仅自动态需要） |
| **图类型决策** | `summarize_chart_data` 偏多折线，需扩充让模型能产出 funnel / 饼结构 | 中 |
| **Excel 形态** | `export_dataset` 为单表；多 sheet / 每图一份需定 | 低 |
| **数据 API 是否存在** | 当前已纳管模块为 battery/chit/kb 等运营模块，**无投放/广告渠道监控接口**；需确认数据侧是否已有 HTTP 接口 | 最高（前提） |

## 5. 待补改造清单（按优先级）

1. **漏斗图注册**：`ResultChart.vue` 引入 `FunnelChart` / `PieChart`，扩展 `ChartView` 类型。
2. **图类型决策逻辑**：系统提示 + 工具 schema 扩展，让模型按数据形态选折线/柱状/漏斗/饼。
3. **调度层（仅自动态）**：外部 cron 或进程内 scheduler 触发无人值守执行，复用现有异步执行 + 钉钉告警。
4. **Excel 导出形态定稿**：单表 / 多 sheet / 每图一份。
5. **数据 API 接入**：投放 ROI 数据接口（挂 backend 或新增 gather/film 类服务），补 operation 描述 + 字段映射，并写入 `data/api-operation-index.json` 索引（`call_api` 据此按 alias/结构/模糊解析路由）。

## 6. 落地路线

### 阶段一：对话式排查 Agent（最快验证价值，几乎不写代码）
- 把投放数据 API 接进 `call_api` 索引 + 配字段映射；
- 系统提示写清「用户问 ROI 时，主动对比昨日/上周同期，异常时按语言/包体下钻」；
- 用户问一句「今天各渠道 ROI 正常吗」，Agent 自动拉数、对比、下钻、给结论 + 出图。
- **数据获取难度高时，可先用 mock 接口把编排跑通**，demo 不受真实数据阻塞。

### 阶段二：可视化交付增强（本方案重点）
- 补漏斗图；固化图类型决策；Excel 导出定型。
- 交付物从「文字结论」升级为「多图 + Excel」。

### 阶段三：自动监控（无人值守）
- 补调度层，把阶段一/二升级为「每日自动巡检 + 异常推钉钉」。

---

## 7. 风险与待确认项

- **最大前提**：投放 ROI 数据 API 是否就绪？决定阶段一能否直接用真实数据。
- 比率指标口径（ROI = 支付金额/消耗？CVR 分母取点击还是曝光？）需业务对齐。
- 若数据 API 仅支持单维筛选，模型下钻需逐维遍历，较慢；建议数据侧提供「异常下钻聚合」接口（channel × language × package 交叉分组）。

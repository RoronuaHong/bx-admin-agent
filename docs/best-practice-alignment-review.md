## 0. 两家产品不要混

| 名字 | 实际是什么 | 和我们比 |
|---|---|---|
| **千问办公网页** | 云端定时任务，关浏览器也跑。[网页端定时任务](https://qwenwork.cn/docs/web/scheduled-tasks) | 最接近：常驻、执行记录、停用后从下一拍继续 |
| **千问办公桌面** | 本机调度，睡眠/关机会错过，建议「保持唤醒」。[桌面端](https://qwenwork.cn/docs/desktop/scheduled-tasks) | 不学「机器必须醒着」；我们是服务端 |
| **Qwen Code `/loop`** | 会话内 cron，默认退出即失，可动态唤醒。[文档](https://qwenlm.github.io/qwen-code-docs/zh/users/features/scheduled-tasks/) | 只学盯盘节奏，不学会话级短命调度 |
| **CodeBuddy CLI `/loop`** | 会话级，退出清除，循环约 3 天过期，错过不补跑。[文档](https://www.codebuddy.cn/docs/cli/scheduled-tasks) | 适合开发者盯 CI，不适合 7×24 预警 |
| **WorkBuddy 自动化** | 本地持久的办公定时任务，跑完可推企微/小程序；权限分默认 / 完全访问。[指南](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Automation-Guide) | 学「先低频试跑、无人值守收权限、结果推 IM」 |
| **WorkBuddy 权限模式** | 非交互时 `default` 会拒绝仍需询问的动作；固定白名单用 `dontAsk` + allow。[权限模式](https://cloud.tencent.cn/document/product/1831/137058) | 学「定时跑不能弹确认框，未批准的写操作应拒绝」 |

千问办公和 CodeBuddy 都强调：**先在普通对话里跑通，再固化成定时任务。** 条件写在指令里，不铺成一级阈值表单。这点和我们已落地的「先测后跑」一致。
